# BASIRA | بصيرة — المرجع الرسمي للمشروع

> Think. Discover. Play. — فكّر. اكتشف. العب.

هذا الملف هو نقطة الحقيقة الأساسية لأي مطوّر أو مساعد أو جلسة عمل على المستودع. عند التعارض، تُقدَّم قرارات المالك الأحدث المسجلة هنا وفي سجل القرارات على أي كود أو وثيقة قديمة.

**آخر تحديث يدوي:** 2026-11-20  
**الحالة العامة:** قيد البناء — لا يوجد إثبات نشر حي للمنصة الكاملة.

## 1. تعريف المنتج — القرار المعتمد

BASIRA منصة عربية للمعرفة والألعاب الذهنية والتعلم الممتع. تجمع محتوى معرفيًا منظّمًا، وأسئلة وتحديات وألعابًا قصيرة، مع تجربة زائر كاملة وحساب اختياري لحفظ التقدم بين الأجهزة.

### حدود النطاق

- نطاق العمل المعتمد هو منصة BASIRA للمعرفة والألعاب فقط.
- لا تُضاف وظائف أو أقسام جديدة إلا بطلب واضح من المالك.
- لا تُخلط BASIRA مع أي مشروع آخر أو تُنقل إليها إعدادات أو بنية غير معتمدة.

## 2. الهوية والتجربة

- الاسم الظاهر: **BASIRA | بصيرة**.
- الشعار: **Think. Discover. Play. / فكّر. اكتشف. العب.**
- اللغة الأساسية: العربية، اتجاه RTL، مع قابلية إضافة الإنجليزية عند اعتمادها.
- تصميم Mobile-first، سريع، واضح، متجاوب، سهل الاستخدام على الهاتف.
- دعم الوضع الفاتح والداكن مع حفظ اختيار المستخدم.
- واجهة رئيسية حقيقية للمنصة، وليست قائمة روابط أو صفحة تعريف فقط.
- الصفحة الرئيسية تعرض: المقدمة/البحث، سؤال اليوم، أقسام المعرفة، الألعاب والتحديات، أحدث المحتوى، التقدم والإنجازات، ومنهجية التحقق.
- يجب أن تكون عناصر التنقل والأزرار وروابط اللعب فعّالة؛ لا تُعرض واجهات شكلية على أنها وظائف مكتملة.
- اسم العلامة BASIRA مستقل عن عنوان Blogger الفرعي. إذا كان عنوان Blogspot محجوزًا، نختار عنوانًا بديلًا متاحًا دون تغيير اسم العلامة.

## 3. أقسام المعرفة المعتمدة

الأقسام الثمانية الموجودة في إعدادات فرع المنصة:

1. العلوم.
2. التاريخ والحضارات.
3. الجغرافيا والدول.
4. التكنولوجيا.
5. الثقافة العامة.
6. الرياضيات والمنطق.
7. اللغة والأدب.
8. الفضاء والفلك.

كل قسم يحتاج وصفًا ومحتوى فعليًا وروابط واضحة. يمكن توسيع الأقسام مستقبلًا بقرار واضح، مع تجنب التكرار أو إنشاء أقسام فارغة.

## 4. الألعاب المعتمدة أولًا

1. اختيار من متعدد (MCQ).
2. صح أم خطأ.
3. ترتيب الأحداث.
4. لعبة الذاكرة.
5. خمّن الكلمة.

### متطلبات كل لعبة

- تجربة لعب فعلية وليست صورًا أو نماذج ثابتة.
- تعليمات واضحة، مستويات صعوبة مناسبة، احتساب نتيجة صحيح، تفسير/تغذية راجعة بعد الإجابة، وحالة نهاية وإعادة لعب.
- أسئلة ومفاتيح إجابة محفوظة في بيانات مراجعة، وليست مولّدة عشوائيًا وقت اللعب.
- لا يُستدعَى نموذج ذكاء اصطناعي أثناء اللعب.
- لا تظهر عبارة «العب الآن» إلا عندما تكون اللعبة قابلة للعب فعلًا؛ وإلا تُوسم «قريبًا» أو «قيد الإعداد».

### سؤال اليوم والتحديات

- سؤال اليوم يتغير وفق اليوم من مجموعة أسئلة معتمدة.
- عرض سؤال اليوم وحده لا يثبت اكتمال محرك الألعاب.
- يمكن إضافة تحديات يومية/أسبوعية بعد اكتمال آلية النتائج ومنع التلاعب.

## 5. الحسابات والتقدم والنقاط

- اللعب متاح للزائر دون تسجيل.
- الحساب اختياري لحفظ التقدم والنتائج والإنجازات بين الأجهزة.
- يمكن حفظ تقدم الزائر محليًا ثم مزامنته عند التسجيل إذا تم اعتماد مزود الحسابات.
- مزود الحسابات لم يُحسم. تُقارن الخيارات المجانية أولًا (مثل Firebase أو Cloudflare Workers/D1 أو Supabase) قبل اعتماد أي خدمة.
- لا تنشئ خدمة مدفوعة أو تتطلب بطاقة/رصيدًا دون موافقة صريحة.
- احتساب النقاط يجب أن يتم بطريقة موثوقة على الخادم عند وجود حسابات، لا بمجرد قبول رقم يرسله المتصفح.
- القاعدة المقترحة في مسودة الخطة: نقطة لكل إجابة صحيحة، مكافأة سرعة صغيرة بسقف، ومنع تكرار احتساب الاختبار نفسه أكثر من مرة يوميًا. تظل هذه القاعدة مقترحًا يحتاج تثبيتًا قبل الإطلاق.

## 6. المحتوى والجودة والتحقق

- المحتوى أصلي ومفيد ومكتوب للقارئ، وليس حشوًا أو صفحات مولّدة آليًا.
- تُراجع المقالات والأسئلة بشريًا قبل النشر.
- توثيق الادعاءات والحقائق والأرقام والتواريخ بمصادر قابلة للفتح والمراجعة.
- إظهار تاريخ آخر تحديث للمعلومات التي تتغير.
- إضافة تفسير للإجابة الصحيحة، وتوضيح حدود المعلومة عند الحاجة.
- لا تنشر محتوى غير متحقق أو أسئلة بإجابات ملتبسة.
- مسودة الخطة اقترحت مقالات لا تقل عن 500 كلمة؛ تعامل معها كمعيار تحريري أولي لا كبديل عن الجودة والفائدة.

## 7. Blogger والنشر

- منصة النشر المستهدفة حاليًا: Blogger بقالب XML يُبنى من ملفات المصدر.
- صفحات التعريف والألعاب تُجهز كملفات مستقلة ثم تُنشر/تُربط وفق خريطة URLs موثقة.
- ملفات البناء ليست دليلًا على أن القالب رُفع أو أن المدونة الحية تغيرت.
- تم التحقق سابقًا من اتصال Blogger OAuth عبر GitHub Actions باختبار قراءة فقط في PR #4. هذا يثبت المصادقة والقراءة، ولا يثبت إمكانية رفع قالب XML.
- Blogger API v3 لا يوفر طريقة رسمية لتحديث Theme XML؛ استعادة القالب تتم يدويًا من لوحة Blogger ما لم تتوفر واجهة رسمية موثقة مستقبلًا.
- لا تستخدم endpoints داخلية غير موثقة، ولا تحفظ كلمة مرور Google، ولا تنفذ أتمتة متصفح غير مصرح بها.
- قبل استيراد محتوى أو مزامنة صفحات: افحص الموجود، وطابق الروابط، وامنع التكرار أو الكتابة فوق صفحات قائمة دون موافقة.
- لا تحذف محتوى المدونة الحية.

## 8. AdSense وSEO

- تصميم المنصة والمحتوى يجب أن يدعما الجودة والثقة وسهولة التصفح.
- صفحات أساسية مطلوبة: عن بصيرة، اتصل بنا، سياسة الخصوصية، شروط الاستخدام، وسياسة تحرير/منهجية التحقق.
- المقالات يجب أن تقدم قيمة أصلية حقيقية، مع بنية واضحة وروابط داخلية ومصادر.
- يلزم فحص العناوين والوصف وcanonical وrobots وsitemap وبيانات structured data وتجربة الهاتف والسرعة.
- **لا يوجد ضمان لقبول Google AdSense**؛ القرار النهائي لجوجل، ولا يُعلن عن جاهزية أو قبول دون أدلة فعلية.
- لا تضع إعلانات أو أكواد تتبع قبل تحديد الحاجة ومراجعة الخصوصية والأداء.

## 9. التقنية والأمان والتكلفة

- الأولوية للحلول المجانية أو ذات الحدود المجانية، بلا تكلفة مقدمة.
- لا تضف اشتراكات أو خدمات مدفوعة أو API يتطلب رصيدًا دون موافقة صريحة.
- لا أسرار أو مفاتيح أو tokens أو كلمات مرور في المستودع أو ملفات الواجهة.
- الأسرار، إن لزمت، تحفظ في GitHub Secrets أو إعدادات الخادم المناسبة فقط.
- لا تستخدم مفاتيح خدمة إدارية في المتصفح.
- الذكاء الاصطناعي مساعد تحرير اختياري فقط، مع مراجعة بشرية، وليس جزءًا من حلقة اللعب.
- لا تنقل بيانات أو مفاتيح أو إعدادات من مشاريع أخرى.

## 11. ما لم يُنفّذ بعد / قائمة العمل

### أولوية حرجة
- اعتماد فرع المنصة بوصفه مصدر العمل الفعلي بدل موقع الحاسبات القديم.
- توحيد مسار التطوير وعدم إبقاء مواصفات المنتج موزعة بين فروع متعارضة.
- تنفيذ قالب الصفحة الرئيسية النهائي ثم فحصه على Blogger الحقيقي والهاتف.
- استكمال الألعاب الخمس بمنطق حقيقي واختبارات لكل لعبة.
- مراجعة بنك الأسئلة والمصادر والتفسيرات.

### أولوية عالية
- اختيار مزود الحسابات بعد مقارنة مجانية وتوضيح التكلفة والحدود.
- بناء الحساب الاختياري وحفظ النتائج والتقدم والإنجازات.
- تنفيذ نظام نقاط آمن ومنع التلاعب والتكرار.
- نشر الصفحات الثابتة وربطها دون تكرار أو حذف.
- إنشاء محتوى أصلي فعلي لكل قسم.

### قبل الإطلاق
- تحديد عنوان Blogger المتاح مع إبقاء العلامة BASIRA.
- اختبار RTL والهواتف والمتصفحات وإمكانية الوصول.
- فحص SEO وsitemap وstructured data وSearch Console.
- مراجعة الخصوصية والحسابات.
- إعداد تقرير جاهزية AdSense واقعي دون ضمان قبول.
- اختبار النسخ الاحتياطي والاستعادة وخطة التراجع.

## 13. قواعد العمل الإلزامية

1. اقرأ هذا المرجع وSTATUS وDECISIONS قبل أي تعديل.
2. لا تعد إلى فكرة موقع الحاسبات أو تستعملها كتصميم أو roadmap.
3. لا تعتبر أي بند «منفذًا» إلا بوجود commit/PR أو اختبار/لقطة/نتيجة تشغيل تثبته.
4. افصل دائمًا بين: مخطط، منفذ بالكود، اجتاز الاختبار، منشور حي.
5. كل طلب جديد يسجل كـ GitHub Issue باستخدام نموذج الطلب، أو يُضاف إلى سجل الطلبات عند تنفيذه.
6. حدّث الحالة والقرارات وسجل النشاط مع كل تغيير مؤثر.
7. استخدم PRs للمراجعة؛ لا تدمج ولا تنشر إلى Blogger دون موافقة صريحة.
8. لا تحذف بيانات أو صفحات Blogger أو محتوى قائم. لا تحذف ملفات تاريخية إلا ضمن PR يوضح الأثر ويحتفظ بما يلزم.
9. لا تعدّل migrations مطبقة، ولا تضع أسرارًا في الكود.
10. لا تضف تكلفة أو خدمة مدفوعة دون موافقة صريحة.
11. في كل PR اكتب بوضوح ما اختُبر وما لم يُختبر.
12. ردود التسليم للمستخدم بالعربية وباختصار، مع روابط وأدلة وحاجز واضح عند وجود عائق.
